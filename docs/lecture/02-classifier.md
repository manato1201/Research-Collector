# 第 2 回 分類の補助(キーワードの重み)

> 所要時間の目安: 2.5 時間 / 前提: 第 0〜1 回・正規表現の基本

## この回のゴール

- キーワードの**重み**で、3 カテゴリのどれかを選ぶ仕組みを説明できる。
- **単語境界**で照合する理由(`api` が `capital` に当たらない)を説明できる。
- **「どれでもない」**と、**確信度**(同点は下げる)の意味を説明できる。
- **出典の事前情報**(ソースの種類)の使い方と、その限界を説明できる。

## 1. 仕組み

カテゴリごとに、**手がかりの語と重み**(1 = 弱い、2 = 強い)の表があります(`_KEYWORDS`)。記事のタイトル(と要約)に含まれる語の**重みの合計**が、カテゴリの**得点**です。最高点のカテゴリを選びます。

- **英字**: 5 文字以上は**部分一致**(複数形・派生語・連結語に対応)。**4 文字以下は単語境界**(複数形の `s` だけ許す)。
- **日本語**: 部分一致。
- **どのカテゴリも `MIN_SCORE`(1)未満**なら、**`none`(どれでもない)**で、人の確認に回す。
- **出典の事前情報**(`_SOURCE_PRIOR`): Unity のタグの記事は、タイトルに「Unity」と書かれていなくても、ゲーム開発に弱い加点(+1)。汎用の出典(arXiv など)は、**事前情報なし**。

```python
# 引用: nbklm/classifier.py::_compile
def _compile(kw: str) -> re.Pattern:
    """
    5文字以上の英字語は部分一致(複数形・派生語・CEDECの「2026ENGVAUnreal」のような連結に対応)。
    4文字以下の短い語は誤爆(例: "api" が "capital" に当たる)を避けるため単語境界で照合し、複数形の s だけ許す。
    """
    if kw.isascii():
        if len(kw) >= 5:
            return re.compile(re.escape(kw))
        return re.compile(r"(?<![a-z0-9])" + re.escape(kw) + r"s?(?![a-z0-9])")
    return re.compile(re.escape(kw))
```

```python
# 実行できる
from nbklm.classifier import classify

titles = [
    ("Nanite の仕組みを読む", ""),
    ("capital markets の話", ""),                 # api が capital に当たらないこと
    ("Public APIs の設計", ""),                   # 複数形の s は許す
    ("ゲームの設計を考える", ""),                 # 2 つのカテゴリに当たる
    ("今日の天気", ""),                           # 何にも当たらない
    ("新機能のお知らせ", "unity"),                 # 出典の事前情報だけで決まる
]
for title, source in titles:
    r = classify(title, source_type=source)
    print(f"{title:18} → {r['label']:22} 確信度 {r['confidence']:.2f}  手がかり {r['keywords']}")
```

## 2. 確信度

`確信度 = 最高点 ÷ 全カテゴリの得点の合計`。**同点首位が複数**あるときは、**0.5 以下に下げる**(決めきれない)。

「ゲームの設計を考える」は、`ゲーム`(ゲーム開発・重み 2)と `設計`(ソフトウェア工学・重み 1)の両方に当たり、確信度は 0.67 になります。

## 3. 「補助」であることの意味

- **実際の振り分けは、ソースの種類で決まる**(この分類は変えない)。分類は、「振り分けが妥当か」を確かめる**補助**で、`agreement_report()` が、**現在の振り分けとの一致率**を自分のデータで測る。
- 公式の分類モデルは英語が最高精度で、日本語は**自データで検証する**必要がある。だから、**キーワード方式**(外部モデル・依存なし)で、**精度は測って確かめる**。
- 将来、モデル方式に替えるときも、`classify()` の**入出力を保てば**差し替えできる。

> **限界**: キーワードの表は**手で書いた**もの。新しい用語(新しいエンジン名など)は、**表に足さないと拾えない**。「どれでもない」が増えたら、表を見直すサイン。

## 確認問題

1. `api` を、部分一致でなく、単語境界で照合するのは、なぜですか。
2. 「どれでもない」を返す利点は。
3. 同点首位のとき、確信度を下げるのは、なぜですか。

## 解答

1. 部分一致だと、`capital` の中の `api` に当たる(**誤爆**)。短い語は、境界で照合する。
2. 自動で無理に分類せず、**人の確認に回せる**(誤った振り分けで、記事が埋もれない)。
3. どれか決めきれない状態を、**呼び出し側に伝える**ため(ラベルは優先順位で決まるが、確信は低い)。

## まとめ

- 分類は**キーワードの重みの合計**。短い英字は単語境界、日本語は部分一致。
- 当てはまらなければ **`none`**(人に回す)。同点は確信度を下げる。出典の事前情報は、弱い加点。
- 分類は**補助**。精度は、自分のデータで測る。
