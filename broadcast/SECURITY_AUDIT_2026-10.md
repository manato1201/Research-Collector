# ResearchBroadcast Worker のセキュリティ点検(2026-10-24)

`IMPROVEMENT_DESIGN_2026-10.md` / `ResearchBroadcast_DESIGN.md` の「外部リソースの追補」X2(security-audit-skill)の進め方に沿って、`broadcast/` の認証・取り込み API・フロントを点検した。
結果は **確定 / 要確認 / 却下** で記録する。

## 進め方(6 段階)

| 段階       | やったこと                                                                                                                                                                                                       |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 偵察       | `src/index.js`(ルーティング・認証)、`src/auth.js`、`src/validate.js`、`public/*.js`、`public/_headers`、`wrangler.jsonc` を読み、入口(公開・Cookie・Bearer)と、外部の入力が届く先(D1・FTS5・AI・DOM)を洗い出した |
| 探索       | 入口ごとに「何を入れられるか」を挙げ、攻撃の候補を作った                                                                                                                                                         |
| 候補の反証 | 各候補を、コードを読んで「成立しない理由」から探した(成立しないものは「却下」へ)                                                                                                                                 |
| 構造化     | 残った候補を、影響・再現手順・対処の形で下に整理した                                                                                                                                                             |
| 独立検証   | 検証役を別のエージェントにする代わりに、**実行できるテスト**で確かめた(攻撃入力を実サーバーに送る統合テスト・単体テスト)。別のエージェントによる検証は、していない                                               |
| 報告       | この文書                                                                                                                                                                                                         |

## 確定(修正済み)

| ID  | 内容                                                                                | 影響                                                              | 再現・根拠                                                                                                              | 対処                                                                                                                                                                           |
| --- | ----------------------------------------------------------------------------------- | ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| S1  | 検索語に NUL 文字(`\u0000`)を含めると、FTS5 の照会が失敗して **500** になる         | 低(データは漏れない。検索が落ちるだけ)。ファジングで見つかった    | `/api/search?q=日本語%00` → 500                                                                                         | 制御文字を空白に置き換える(`parseSearch`)。回帰テストを追加                                                                                                                    |
| S2  | ログインの総当たり対策が「失敗後の 0.8 秒の待ち」だけで、**並列に試せば回避できる** | パスワードが短ければ中〜高。20 文字以上のランダムなら実害は小さい | 並列リクエストでは、待ちが直列にならない                                                                                | IP ごとの試行制限を追加(8 回失敗 / 15 分で 429。合っているパスワードでも拒否。IP はハッシュで保存。D1 が使えないときは制限せず、パスワード確認だけで進める)。`src/throttle.js` |
| S3  | ログアウトに Origin の確認が無く、他のサイトから**強制的にログアウトさせられる**    | 低(迷惑のみ)                                                      | 他サイトの `fetch("/api/logout", {method: "POST"})`(SameSite=Strict の Cookie は付かないが、ログアウトの要求自体は通る) | Origin が同じでなければ 403                                                                                                                                                    |
| S4  | API の JSON 応答に `X-Content-Type-Options: nosniff` が無い                         | 低(防御の厚み)                                                    | 応答ヘッダーの確認                                                                                                      | 付けた                                                                                                                                                                         |

## 要確認(運用・残るリスク)

| ID  | 内容                                                                                                        | 判断                                                                                                                                                               |
| --- | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| S5  | 試行制限は **IP 単位**。多数の IP に分散した総当たりには効かない                                            | パスワードを長いランダム文字列にする(現在の発行は 20 文字・約 115 ビット)。Cloudflare の有料機能(Rate Limiting の追加ルールなど)は、無料プランの方針により使わない |
| S6  | セッションは 30 日有効で、**個別には失効できない**(パスワードを変えると全て失効する)                        | 受け入れる。端末の紛失時は、パスワードを再発行する(手順は `broadcast/README.md` の `wrangler secret put VIEW_PASSWORD`)                                                                                                |
| S7  | 試行制限は `cf-connecting-ip` を信頼する。Cloudflare 経由では偽装できないが、**ローカル開発では偽装できる** | 本番では問題なし。テストが偽の IP で動くのは、このため                                                                                                             |

## 却下(問題なしと確認)

| ID  | 候補                                        | 根拠                                                                                                                                                                                                                                   |
| --- | ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | SQL インジェクション                        | 値はすべて `bind`。動的な SQL は、許可リストのテーブル名と、コード内の固定の断片だけ。敵対的な 21 種の文字列 × 7 つの経路で 5xx なし(統合テスト)                                                                                       |
| R2  | 保存型 XSS                                  | `innerHTML` / `outerHTML` / `insertAdjacentHTML` / `document.write` / `eval` / `new Function` が **0 件**(単体テストで固定)。リンクは http(s) のみ。CSP は `script-src 'self'`・`unsafe-inline` / `unsafe-eval` なし(単体テストで固定) |
| R3  | 認証の比較・Cookie                          | トークン・パスワードは SHA-256 後の定数時間比較。Cookie は HttpOnly・SameSite=Strict・Secure、HMAC 署名と期限つき                                                                                                                      |
| R4  | Cookie 認証の書き込みの CSRF                | Origin が同じでなければ 403(ボード・設定・ログイン・ログアウト)                                                                                                                                                                        |
| R5  | 機械用 API の越権                           | 取り込み・解説の生成・書き出しは Bearer のみ。Cookie では不可(統合テスト)                                                                                                                                                              |
| R6  | トークンの強度                              | 64 文字                                                                                                                                                                                                                                |
| R7  | エラーでの情報漏えい                        | 応答は `internal_error` 固定。内部のメッセージはログだけ                                                                                                                                                                               |
| R8  | プロンプトインジェクション(記事の本文 → AI) | AI に道具が無い。出力は、JSON・日本語・URL 除去・綴りの検査を通し、`textContent` で表示する。起こりうるのは「誤った説明の表示」までで、「AIの解説」と明示している                                                                      |
| R9  | 大きな本文での負荷                          | 本文を上限つきで読む(取り込み・ボード・設定・ログイン 2KB)                                                                                                                                                                             |
| R10 | 秘密情報の混入                              | `.dev.vars` / `.deploy-secrets.txt` は `.gitignore`。`public/`(配信される範囲)に秘密は無い                                                                                                                                             |

## 残した確認

- 本番へのデプロイ後、ログインの制限(429)を本番で再現する検証は、していない(自分のログインを塞ぐため)。ローカルの統合テストと、D1 を模した単体テストで確認した。
- Worker の依存は無い(外部のライブラリを使っていない)ため、依存の脆弱性の点検は対象外。
